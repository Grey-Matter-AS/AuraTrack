## Slice 2: Decisions to confirm (ROADMAP B4)

I propose each one; you answer yes or change it. The answers go into `decisions/` and `STATUS.md`.

| # | Decision | Proposal | Why |
|---|---|---|---|
| 2.1 | **Version scheme** | The first store release is **1.0**; both platforms carry the same version number for the same feature set. The build number counts up on its own. | The name already holds the 7, and "AuraTrack7 7.0" reads oddly. The PWA keeps its own 7.x numbers. |
| 2.2 | **Reverse-domain id** | `eu.greymatter.auratrack7` on both platforms | The domain is `grey-matter.eu`. The plain reverse, `eu.grey-matter`, works on Apple but not on Android, because Android ids can't contain hyphens. Android's own rule would give `eu.grey_matter`, but Apple ids can't contain underscores. Dropping the hyphen gives one id that is valid on both. Neither store checks domain ownership; the id only has to be unique. **An id can never be changed after the first upload.** |
| 2.3 | **Apple ids** | app `eu.greymatter.auratrack7` · watch app `…auratrack7.watchkitapp` · widgets, Live Activities and controls `…auratrack7.widgets` · notification service `…auratrack7.notificationservice` · push provider `…auratrack7.pushprovider` · app group `group.eu.greymatter.auratrack7` | Apple's naming pattern; one app group shares the store between app and extensions. |
| 2.4 | **Android ids** | `applicationId eu.greymatter.auratrack7` for the phone **and** the Wear OS app (the Data Layer requires the same id and the same signing key); the same id in the `fdroid` build | One id per platform keeps it simple; F-Droid signs with its own key, so the two builds can't be installed over each other, which is normal. |
| 2.5 | **Display name** | **AuraTrack7** on every home screen, watch and store | Settled in D-1. |
| 2.6 | **Security contact** | `security@grey-matter.eu`, plus GitHub's private vulnerability reporting switched on for the repository | Researchers expect both; the address goes into `SECURITY.md` in N1. |
| 2.7 | **Texts for Apple** | I draft the Critical Alerts request, the Local Push Connectivity request and the App Review question in `docs/AuraTrack7/apple-requests.md`; you send them | Careful, neutral wording (no "detects", "life-saving"). |
